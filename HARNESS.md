# Project Operating Contract (`HCP-SPEC-003` — Phase 2 Dedicated Runtime)

## Operating Boundaries
- Allowed scope: Modify only files explicitly assigned in the active task contract (`.agents/brain/state.md`).
- Forbidden actions:
  - Never retain or reintroduce any external third-party orchestrator adapter, legacy POC artifact, or unapproved environment variable.
  - Never add unverified external dependencies outside the approved allowlist in `.agents/brain/state.md`.
  - Never allow `/apps/api` or `/apps/web` to access `/var/run/docker.sock` (`InaccessiblePaths=/var/run/docker.sock`); Docker Engine socket access is strictly confined to the isolated `hp-docker-executor` daemon (`ADR-010`, `AC-F2-01`).
  - `apps/api` never starts an external program, with one exception: `apps/api/src/backups/panel-dump.ts` runs `/usr/lib/postgresql/18/bin/pg_dump` through `execFile` (static absolute path, no shell, credentials only in the environment of that child; `ADR-022` §6; guarded by test 1 of `apps/api/test/phase2-api.integration.test.ts`).
  - Never mount `/var/run/docker.sock` inside the Data Plane ingress proxy (`hp_ingress_proxy` / Traefik v3 uses read-only Dynamic File Provider only — `ADR-014`, `TH-02`, `AC-F2-03`).
  - Never invoke `sh -c`, shell command interpolation, or unapproved OS binaries in `hp-host-agent` (`execFile` on static absolute paths and closed enums only — `AC-F2-04`). The agent's programs are `nft` (`/usr/sbin/nft` or `/usr/bin/nft`), `/usr/bin/uname`, `/usr/bin/df`, `/usr/bin/systemctl`, `/usr/bin/journalctl` and `/usr/bin/apt-get`, with `shell: false`, the fixed environment `PATH` and `LC_ALL=C`, and `systemctl`, `journalctl` and `apt-get` accepted only as whole closed argument lists (R198 2.1). Root work goes only through the fixed root units `hp-unit-restart@<service>`, `hp-panel-update`, `hp-os-refresh` and `hp-os-upgrade`, started by their path units when the agent writes an empty trigger file in `/run/hosting-panel/host-jobs`; the agent never starts them itself and never chooses their command (ADR 0028).
  - Never expose raw Docker container/network/volume IDs, socket paths, host filesystem paths, ciphertexts, or plaintext secrets in public DTOs, `StackRevision` specs, `outbox_events`, `Config.Env`, or logs (`F1-008`, `F1-012`, `ADR-015`, `AC-F2-05`). One exception: an environment secret of an `HCP-STACK/v2` application template, which only `hp-docker-executor` writes into `Config.Env` of that stack's own container and never returns (`ADR-0036` §2.5).
  - Never blindly replay mutating `POST` IPC calls for operations in `unknown` state (`TH-08`, `AC-F2-07`), and never let the Drift Reconciler restart or recreate running tenant containers autonomously (`TH-10`, `AC-F2-08`).
  - Never let the API, a customer or a client choose a local backup path or `RESTIC_REPOSITORY` (the root is the executor's `HP_BACKUP_LOCAL_ROOT`; `ADR-0032`), never put a PEM, a private key or an S3 secret in a DTO, audit row, outbox payload, log, URL or container environment (`ADR-0031`), and never publish a manual certificate hot unless it deterministically wins the SNI selection (`ADR-0031` §2.7).
  - Never enable `Shared Hosting` (`409 SHARED_MODE_GATED`) or close `ADR-011` (`OPEN — prima di Shared`) (`AC-F1-06`, `AC-F2-10`).
  - Never claim a capability whose flag is still `false`; flags turn `true` only when the feature ships per `docs/superpowers/specs/2026-11-08-production-hosting-panel-design.md`.
  - Never enable dev OIDC or demo seeding by default (`ENABLE_DEV_OIDC` and `HP_SEED_DEMO` stay `false` outside dev launchers).
  - Never let one restore container mount both the site's volume and the staging volume (R207 `restore.1`; guarded by `apps/docker-executor/test/restore-volumes-apart.test.ts`).
  - Never let a site reach the cloud metadata address: the base rules' `forward` chain drops bridge traffic to `169.254.0.0/16` (DNS port 53 excepted) and to `fd00:ec2::254` (R207 `host.1`; guarded by `apps/host-agent/test/m5d-host-qa.test.ts` P7).
  - Never open the generic service routes (`createService`, `appendServiceRevision`) or `createInvitation` to anyone but a server administrator who reaches the organisation, and never let the executor accept limits above the ceiling (64 GiB, 64000 milli CPU) or a host port the server uses (R207 `orgs.2`, `exec.1`, `exec.2`, `a.1`; guarded by `apps/api/test/admin-only-routes.integration.test.ts`, `apps/api/test/support-access-tenancy.integration.test.ts`, `apps/docker-executor/test/service-spec-limits.test.ts`, `apps/docker-executor/test/docker-executor.test.ts` and `packages/policy-engine/test/policy-engine.test.ts`).
  - Never let anyone but a server administrator create or change a site template, and never store or render a template version the policy engine has not validated: the executor takes a template's image and settings only inside the approved spec, never a path or a Compose key (`ADR-0033`; guarded by `apps/api/test/site-templates.integration.test.ts`, `packages/policy-engine/test/site-template-security.test.ts` and `apps/docker-executor/test/site-php-wiring.test.ts`).
  - Never let anyone but a server administrator create, version or publish an application template; never accept in a template or a stack plan a key outside the allowlist, a host path, `docker.sock`, a host port, a capability, `privileged`, a shell as `argv[0]`, an image without digest or, for an `HCP-STACK/v1` template, an image outside `APP_IMAGE_ALLOWLIST`; never let a template or a plan say anything about a container's privileges except the closed run profile name of `HCP-STACK/v2` (`strict` or `standard`, whose meaning is a constant of the executor); never put a stack secret in a plan, revision, preview, outbox row, audit row or log, and in `Config.Env` only as a v2 environment secret written by the executor; never let a customer import Compose, choose an image or read a generated secret; never attach a stack container to a platform network or the proxy to a stack's private network (`ADR-0035`, `ADR-0036`; guarded by `packages/policy-engine/test/app-template-security.test.ts`, `packages/contracts/test/app-stack-plan.test.ts`, `apps/docker-executor/test/app-stack-payload.test.ts`, `infra/linux/accept-app-stack-http-cache.mjs`, `infra/linux/accept-app-stack-worker-storage.mjs` and `infra/linux/accept-app-stack-wordpress.mjs`).
  - Never let a customer or a template write proxy configuration: an application address takes only the closed routing options (redirect to another address of the same application, password protection, compression, up to four path rules to ingress targets of the same plan), and the executor re-checks every value before it writes the route file; never put the password of an address, or its `$apr1$` verifier, in a DTO, audit row, outbox payload, operation or log (the verifier lives only in the database row, the signed route request and the route file; the password is stored nowhere) (`ADR-0037`; guarded by `packages/contracts/test/app-stack-routing.test.ts`, `apps/api/test/app-stack-routing-options.qa.test.ts`, `apps/docker-executor/test/app-stack-route-options.test.ts` and `infra/linux/accept-app-routing-options.mjs`).
  - Never copy or write back the data of an application while one of its containers runs, nor start, create or remove its containers while such a job of it may still run; never let a backup job of an application mount a volume that is not that application's own, a writable volume during a copy or more than one volume during a restore, carry the label `io.hostingpanel.stack_id`, keep a capability beyond `DAC_READ_SEARCH` (copy) or `CHOWN`, `DAC_OVERRIDE`, `FOWNER`, `FSETID` (restore), or open a repository other than `stacks/<stackId>` of its own application; never write a backup back before the safety backup of the data as they are has one good copy, and never send a restore a second time when its answer was lost; never put the name or the path of a destination, a snapshot id or the name of a Docker volume in an application backup DTO, audit row, outbox payload or operation (`ADR-0038`; guarded by `apps/docker-executor/test/app-stack-backup-jobs.test.ts`, `apps/docker-executor/test/app-stack-backup-runner.test.ts`, `apps/docker-executor/test/app-stack-engine.test.ts`, `apps/api/test/app-stack-backup-runtime.unit.test.ts`, `apps/api/test/app-stack-backups.integration.test.ts` and `infra/linux/accept-app-stack-backups.mjs`).
  - Never attach an application component to a network that is not its own application's, with one exception: the executor may attach the single component of a database application to the private network (`hp_appnet_*`) of another application of the same customer, under the name it derives itself from the database's id, after it has checked the labels of the container and of the network; never to an edge network, a platform network, the proxy's network or a network of another customer; never remove an application's private network while a component of another application is still attached to it; never give a component a temporary area other than `/tmp` and the ones its image's row in `APP_IMAGE_ALLOWLIST` declares; never return a Docker network or container id from a link call, and never fail, restart or recreate a component because a link could not be applied (`ADR-0039`; guarded by `apps/docker-executor/test/app-stack-links.test.ts`, `apps/docker-executor/test/app-stack-payload.test.ts`, `apps/api/test/app-stack-links.integration.test.ts` and `infra/linux/accept-app-stack-databases.mjs`).
  - Never let `hp-docker-executor` or `hp-host-agent` call an address chosen by a user; the API makes outbound HTTP requests only from `apps/api/src/notifications/outbound-http.ts`: only `https://` to a DNS name whose every resolved address is public and is not one of this server's own, connecting to the address it checked, following no redirect and reading no response body; never put the address of a webhook, its signing key or a Telegram bot token in a DTO, audit row, outbox payload, operation or log (they are encrypted at rest; a page shows the host name and the chat only); never put text typed by a user in a notification except the bounded, cleaned names of an event, and never in the subject of a mail; never tell a customer's channel of another customer's site or of an alert outside `CUSTOMER_NOTIFICATION_KINDS` (`ADR-0040`; guarded by `apps/api/test/notification-outbound-http.unit.test.ts`, `apps/api/test/notifications.integration.test.ts`, `packages/contracts/test/notifications.test.ts`, `packages/database/test/notifications-database.test.ts` and `apps/docker-executor/test/panel-mail.test.ts`).

## Verification Protocol (Objective Sensors)
Before marking any unit complete or merging into `main`, run these checks in order:
1. Build Check: `corepack pnpm run build`
2. Linter: `corepack pnpm run lint`
3. Typecheck: `corepack pnpm run typecheck`
4. Test Suite: `corepack pnpm run test`
5. Clean-Room & Phase 1/2 Contract Check: Verify zero legacy remnants in code/config and full compliance with `AC-F1-01`..`AC-F1-10` and `AC-F2-01`..`AC-F2-10` via independent `swarm-verifier`.

## Failure Escalation
If a test or sensor fails twice consecutively on the exact same error with zero progress:
- Stop autonomous editing immediately
- Print the exact error log
- State the proposed fix and wait for user confirmation
